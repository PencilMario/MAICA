# LanceDB embedded vector store design

## Intent

Replace Milvus with an embedded LanceDB vector store so MAICA RAG and
`maica-gnrc` work on Windows without a separately deployed database and remain
packagable as a Nuitka one-file application.

The embedding service remains OpenAI-compatible and external to this change.
Existing Milvus data and remote-Milvus compatibility are intentionally not
preserved.

## Baseline

The design is based on these current owners:

- `maica/maica_utils/connection_utils.py` owns the Milvus connection.
- `maica/maica_utils/connection_mixin.py` owns embedding-assisted insert and
  search behavior.
- `maica/initializer/migrations/migration_4.py` creates the Milvus collection.
- `maica/maica_utils/session_late.py` and `maica/mtools/generic/rag.py` consume
  the vector store for user RAG and `maica-gnrc`.
- `maica/env_basis` and `build_local.ps1` define deployment and Nuitka inputs.

Milvus Lite is not a viable Windows backend: the published `pymilvus` package
only installs `milvus-lite` when `sys_platform != "win32"`.

## Architecture

### Storage owner

Introduce one LanceDB connection manager as the sole owner of the embedded
database. It exposes backend-neutral operations for synchronization, search,
initialization, and close. Business code must not import LanceDB or use
Milvus-specific names.

The default database location is `fs_storage/vector_db`, resolved through the
existing MAICA path helpers. It must remain outside Nuitka's temporary one-file
extraction directory.

LanceDB's Python API is synchronous. Every potentially blocking database call
runs through `asyncio.to_thread()` so HTTP and WebSocket event loops remain
responsive. Writes to the shared table are serialized with one async lock.

### Schema

One table serves `maica-gnrc` and per-user RAG. It retains the current logical
fields:

- `id`: stable record identifier generated by MAICA.
- `user_id`: `-1` for the generic dataset, otherwise the MAICA user ID.
- `chat_session_num`: session scope, defaulting to zero where unused.
- `type`: record category.
- `raw_text`: embedded source text.
- `is_prod`: production-state flag.
- `vector`: fixed-size float vector using `MAICA_EMBEDDING_DIMS`.

Scalar predicates are translated to LanceDB filters. Vector search uses cosine
distance. The adapter converts LanceDB distance to similarity with
`similarity = 1 - distance`, preserving the existing rule that a larger value
is a better match and keeping current confidence thresholds meaningful.

### Data synchronization

Synchronization keeps the existing diff behavior:

1. Read records within the supplied scalar scope.
2. Compare stored `raw_text` values with the requested set.
3. Delete stale records.
4. Request embeddings only for newly added text.
5. Insert new records with their scope fields and vectors.

`maica-gnrc` reloads JSONL datasets and repopulates missing or changed rows at
startup. User vectors can likewise be rebuilt from the relational database.
No Milvus import path is provided.

### Search

Search embeds the query through the existing OpenAI-compatible embedding
connection, applies the requested scalar scope, asks LanceDB for the nearest
rows, converts distance to similarity, applies the confidence threshold, and
returns the matching `raw_text` values.

The public application-facing methods use vector-store terminology rather
than names such as `to_milvus`, `filter_milvus`, or `MilvusSearchMixin`.

## Configuration and lifecycle

Replace `MAICA_MILVUS_ADDR`, `MAICA_MILVUS_USER`,
`MAICA_MILVUS_PASSWORD`, and `MAICA_MILVUS_COLL` with
`MAICA_VECTOR_DB_PATH`. The default is `fs_storage/vector_db`.

RAG readiness requires both a usable LanceDB connection and a usable embedding
connection. On shutdown, MAICA releases the vector-store manager alongside
its other shared connections.

On initialization, the manager validates that an existing table's vector
dimension matches `MAICA_EMBEDDING_DIMS`. A mismatch disables RAG with a clear
diagnostic rather than returning invalid results. LanceDB or embedding startup
failure disables RAG and `maica-gnrc`, but does not prevent core chat services
from starting.

## Nuitka compatibility gate

Before business migration, build a minimal probe that:

1. creates a LanceDB database and table;
2. inserts filtered vector records;
3. performs cosine search;
4. exits and reopens the external database;
5. repeats the search from a Nuitka one-file executable.

The build must explicitly collect LanceDB, PyArrow, and required native
libraries. Only a passing Windows probe permits the application migration to
proceed. This gate addresses package feasibility; it does not introduce a
runtime fallback backend.

## Verification

Offline tests cover:

- initial table creation and dimension validation;
- add/delete diff synchronization without re-embedding unchanged text;
- generic and per-user scalar isolation;
- Top-K ordering and similarity-threshold conversion;
- persistent results after closing and reopening the database;
- serialized concurrent writes;
- graceful RAG disablement when initialization fails;
- cleanup and release during shutdown.

The existing Milvus smoke test becomes a LanceDB smoke test. The Nuitka probe
is a separate packaging verification because ordinary unit tests cannot prove
native-library collection.

## Compatibility boundary and non-goals

- Remote Milvus and existing Milvus data are not supported or migrated.
- The embedding API, embedding model selection, and reranker API are unchanged.
- The relational database remains the source of truth for rebuildable user
  content; LanceDB remains derived retrieval storage.
- This change does not bundle a local embedding model.
- This change does not add multiple vector-store providers or automatic
  fallback to SQLite, USearch, Qdrant, or Chroma.

## Impact statement

The change affects dependency declaration, environment configuration,
connection lifecycle, vector synchronization/search, migration initialization,
Nuitka collection flags, documentation, examples, and offline tests. Core
generation APIs and relational persistence contracts remain outside scope.
